# مطابقة دفعة 11 نوفمبر مع API الفعلي — تقرير تنفيذ
**تاريخ الفحص:** 11 نوفمبر 2026. **الحالة:** BLOCKED / غير جاهز للإدخال. **الفرع:** `review/daily-2026-11-11-legal-stories`. هذه مراجعة ثابتة للكود الحالي في `main`؛ لم تُنفذ طلبات إلى قاعدة بيانات الإنتاج.

## ما كشفه الكود
تمت قراءة الملفات الفعلية:
- `backend/app/api/judgment_review.py`
- `backend/app/models/judgments.py`
- `backend/app/services/judgment_publication_policy.py`
- `backend/app/api/judgment_library.py`
- `frontend/data/appeal-cases.json`
- `frontend/scripts/check-appeal-cases.mjs`

### شرط إنشاء مسودة حكم
المسار `POST /admin/judgments/drafts` يتطلب **جلسة مدير** وحقول `source_id`, `court_id`, `case_number`, `year`, `judgment_date`, `full_text` بطول لا يقل عن 100 حرف. ويتطلب أن يكون `source_id` سجل مصدر موجودًا بعنوان HTTPS صالح، وأن تكون المحكمة مسجلة مسبقًا، وألا يكون هناك حكم بنفس `court_id + case_number + year`. تُحفظ المسودة `status=draft` فقط ويُكتب سجل تدقيق.

### لماذا لا يمكن استيراد الأربعين الآن؟
- **39 من 40** لا تحتوي في الفهرس على رقم طعن وسنة وتاريخ حكم ومصدر قانوني مُهيكل، و**الأربعون جميعًا** تفتقر إلى `source_id` و`court_id` الفعليين من قاعدة البيانات. حتى A-21، التي تحمل رقم الطعن وتاريخه، تفتقر إلى معرفَي قاعدة البيانات. **هذا توصيف لحقول الفهرس، وليس بالضرورة غياب المعلومات من النصوص البحثية.**
- `full_text` مطلوب بوصفه نص حكم عند إدخال الأحكام في مكتبة القضاء؛ الملخصات السردية ليست بديلًا عن الحكم القضائي الأصلي. لا يجوز وضع نص قصة مختلق في حقل `full_text`.
- **قسم «القانون على أرض الواقع» مختلف عن مكتبة الأحكام:** لا يوجد في هذه الواجهة مسار لإنشاء قصة سردية مستقلة. لا يجوز خلط القصص العشرين مع أحكام `/admin/judgments/drafts`.
- سجل `frontend/data/appeal-cases.json` يطبق مخططًا آخر يتطلب `appealNumber`, `appealDate`, `firstJudgment`, `challengedJudgment`, `appealOutcome`, `secondarySources`. لا تتطابق مسودات البحث مع هذا المخطط تلقائيًا، كما أن حالة `verified` تتطلب مصدرًا رسميًا من نطاق محكمة النقض ومراجعة بشرية.
- سياسة النشر تمنع الاعتماد دون التحقق من المصدر والاقتباسات والخصوصية، ومصدرين مستقلين، وموافقة بشرية. نشر الأحكام تلقائيًا معطل افتراضيًا.

## مخرجات قابلة للاستخدام دون تعريض الموقع للخطر
1. فهرس `2026-11-11-review-manifest.json` سليم من حيث العدد ومعرّفات المراجعة؛ لكنه `importable=false`.
2. لا يُحوّل أي مرشح إلى حمولة API حتى تُستخرج **حقول المحكمة والقضية والحكم من مصدر أصلي**، وتُربط بمعرفات مصدر ومحكمة موجودة.
3. القصص الواقعية تحتاج مسار نشر مستقل ومراجعة محتوى، ولا يمكن إدخالها عن طريق API الأحكام.
4. يجب أولًا تدقيق المخزون الحالي في `frontend/data/appeal-cases.json` وبيانات الإنتاج لمنع التكرار.

## نتيجة الاختبار
**PASS (static review):** تحديد واجهة الإدخال الفعلية، الحقول المطلوبة، شروط رفض التكرار، وقواعد النشر.  
**NOT RUN:** اختبارات backend، طلبات API، قراءة قاعدة البيانات الحية، مراجعة أصل الأحكام، أو نشر القصص.  
**القرار:** لا إنشاء مسودات إنتاجية ولا نشر دون استكمال المتطلبات.
